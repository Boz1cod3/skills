# Контрольный прогон версии 1.1

Как проверить, что новая версия дешевле и не хуже старой, на одном и том же брифе.

## Бриф

`~/Documents/VScode/Autopilot 2 test/brief.md` — исходный текст брифа прогона News Search 2 (30.09.2026) без «Дополнений», то есть то, что пользователь надиктовал до первых вопросов.

Сравнение не идеальное: базовая линия шла в режиме interview с ответами пользователя, контрольный — в full. Смотреть на доли и абсолютные цифры по ролям, а не только на итог.

## Прогон

В **новом окне**, открытом в папке `Autopilot 2 test`:

```
/autopilot full brief.md Это контрольный прогон: платные сервисы (Apify, Exa, Firecrawl) и Telegram — только через адаптеры с заглушками, реальных вызовов и отправок не делать.
```

## Что сравнить после

```bash
python3 tools/measure-run.py "$HOME/Documents/VScode/Autopilot 2 test"
```

1. **Итог и доли по ролям** против таблицы выше. Ожидание: ревью + ремонт заметно ниже 26 %, оркестратор ниже 37 %.
2. **Время** — по дашборду прогона (`.autopilot/dashboard.html`): «в работе» против 110 минут.
3. **Качество** — блок «Слепая приёмка» на дашборде и раздел «Открытые вопросы» в отчёте: сколько требований подтверждено и сколько расхождений.
4. **Сработали ли правила**: ревью до коммита было только у фундамента и рискованных тасков; дозапросы несли только блокирующее; `state.js` не правился руками (в логе оркестратора нет Edit по `state.js`); в конце было одно ревью всей ветки.

## Результат — 1 октября 2026

Прогон 1.1 (`full`, T2, 6 тасков + 2 таска ремонта ветки) против первого захода News Search 2 на 1.0 (`interview`, T2, 7 тасков). Норм. единицы `measure-run.py`.

| | 1.0 | 1.1 | |
|---|---|---|---|
| **Всего** | 29,4 млн | **21,1 млн** | −28 % |
| Оркестратор | 10,7 млн · 301 шаг · ср. контекст 235K | **5,8 млн** · 187 шагов · 189K | −46 % |
| Исполнители тасков | 9,3 млн | 6,8 млн | −27 % |
| Ревью (точечные, ветки, повторные) | 6,8 млн | 3,4 млн | −51 % |
| Ремонт и таски ремонта ветки (F1, F2) | 0,9 млн | 3,0 млн | работы больше: нашли и починили больше |
| Приёмка, G2, память, ADR | 1,4 млн | 1,8 млн | |
| Время по часам | 145 мин (с интервью) | 96 мин (без ожиданий пользователя) | |

Что сработало как задумано: ни одной ручной правки `state.js` (58 вызовов `ap.py`); точечное ревью — только у трёх помеченных тасков; дозапросы несли блокирующее дословно; рутина, память и ADR — на Sonnet; коммит плана, коммиты по зонам и финальный коммит списком — `brief.md` пользователя остался незакоммиченным. Приёмка из чистого клона нашла три настоящих расхождения (cron падает в свежей копии, не указан Python 3.11+, неточное описание пробного запуска) — их закрыл таск F2 до сдачи. Тестов 242.

Что подкрутили по итогам: таск F1 (ремонт ветки) прошёл три повторных ревью и свежий перезапуск — ревьюер находил всё новые обходы санитайзера; это 3,2 млн и ~27 минут из 36 на этапе ревью. Теперь не больше двух повторных ревью на таск, ещё один обход того же условия — «не закрыто», а не новая находка. И оркестратор однажды запустил субагента, чтобы просто подождать, — теперь ожидание волны это конец хода.

Оговорка: по одному прогону на версию и разные режимы, так что цифры — направление, а не точное измерение.
